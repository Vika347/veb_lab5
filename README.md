# Лабораторная работа №5 — Student Management

SvelteKit + Java (Jakarta EE / Payara) + PostgreSQL.

## Запуск

1. Установить Docker Desktop, запустить его.
2. В корне проекта скопировать `.env` в `.env` (`Copy-Item .env.example .env` в PowerShell).
3. В `.env` указать свой пароль PostgreSQL и случайный JWT_SECRET длиной не менее 32 байт.
4. `docker compose up --build`
5. Открыть http://localhost:3000 после завершения развёртывания Payara.

API: http://localhost:8081/student-management/api. PostgreSQL: localhost:5433.

При первом запуске создаются 1000 тестовых студентов и локальные аккаунты: `admin` / `Admin12345!`, `user` / `User12345!`. Не использовать эти пароли вне локальной лабораторной. Если база уже была создана, SQL инициализации повторно не выполняется. Для полного сброса тестовой базы (удаляет все её данные): `docker compose down -v`.

## Запуск frontend отдельно

`docker compose up --build postgres payara`, затем `cd frontend`, `npm install`, `npm run dev`. Открыть http://localhost:5173. API по умолчанию локальный, можно задать JAVA_API_URL в `frontend/.env`.

## Распределение

- iragrom — студенты, CRUD, поиск, RxJS, BroadcastChannel, SSR списка и досье, кеширование, валидация, loading и ошибки.
- Vika347 — SvelteKit, маршруты, layout, авторизация, JWT, cookies, профиль, API-клиент, Docker, общие стили.

Java-backend перенесён из ЛР4. Добавлен защищённый GET /auth/profile. Логика CRUD и ролей осталась в Java. Старый HTML-интерфейс сохранён внутри WAR, для ЛР5 использовать порт 3000.

## Проверка

- Войти как USER: список доступен, добавление и изменение запрещены (в том числе прямой URL).
- Войти как ADMIN: добавить, изменить, удалить студента, проверить валидацию и уникальность ИСУ.
- Проверить поиск по ФИО, 1–2 фильтра (GET Java), 3 и более (QUERY Java), сортировку, пагинацию.
- Открыть две вкладки, изменить/удалить студента в одной, проверить обновление другой.
- Проверить профиль, выход из двух вкладок, обновление страницы и истечение accessToken.
- Проверить SSR: исходный HTML списка после входа содержит студентов, а не только пустой контейнер.
- Проверить 404, ошибки API, индикатор загрузки, мобильный вид и тему.

Кеш списка в памяти SvelteKit, TTL 30 секунд, очистка после изменений через frontend. JWT находится в HttpOnly cookies. Для HTTPS установить COOKIE_SECURE=true и корректный ORIGIN.

## Автоматические тесты

В папке frontend выполнить `npm test` (Node.js 22). Тесты проверяют выбор GET/QUERY и правила валидации. Для сборки: `npm install`, `npm run build`.

Проверка при подготовке архива: синтаксис JavaScript и модульные тесты выполняются без внешних зависимостей. Полный запуск Docker и сборка SvelteKit в среде подготовки не выполнены: недоступен npm registry и нет Docker/Maven.
